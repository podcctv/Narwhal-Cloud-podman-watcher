# 运维中心 v1.7 使用与验证

## 升级顺序

1. 先部署 Server v1.7.0（自动迁移为新增表，不删除原始表）。
2. 再按已有安装方式更新 Client。旧 Client 可以继续报告，但健康、日志发现、服务探测和管理升级显示不可用。
3. 打开「运维中心」检查报告时间与来源。未配置/权限不足/解析失败/离线不是正常的零流量。

## 采集与流量

账本优先以 `traffic_counters` 累计字节的差值计量；重复/旧时间样本忽略，进程/容器 epoch 变化或计数下降视为重置。超过报告间隔 2.5 倍的间断不补算。计数不可用时采用最新速率乘有效间隔，标注估算。小时/天边界采用 UTC+8 分摊；不用于财务精确计费。小时保存 30 天，日保存 400 天，总汇总行数也有上限。

汇总从部署后采集开始，不追溯估算历史数据。数据库文件清理后可复用空闲页；若要缩小现有文件，使用 `server/maintain_db.py` 的停服备份/压缩流程，勿在线 VACUUM 大文件。

## 风险与策略

general/web/socks/hy2 是可调起步值，不存在适用于所有机器的统一公认流量阈值。主机策略为默认，容器覆盖优先；临时静默最长 24 小时，仅影响新的运维信号，不解除既有弱认证、矿工、非法面板处置。

基线需要最近一天至少 24 个、跨度一小时的样本，流量与连接均超过基线倍数和业务底线，连续三次才触发。异常样本不写入正常基线。基线/配额/策略信号进入原有告警与通知通道，但不自动停止业务。

弱认证/面板/恶意进程的服务端处置在执行回执后等待两次新安全扫描复查；须有进程采样，关闭安全或采集失败不算通过。复发最多重新下发两次，重试执行失败或持续风险可在复查页查看；一小时无新采样标无法确认。Client 原有直接自动处置仍保留自身证据验证与本地策略。

## 日志向导

发现任务只在对应节点运行，检查 `/var/log/nginx`、`/var/log/caddy`、`/var/log/apache2` 及已有配置中的文件。预览仅上报方法/状态码/格式/成功失败计数，不上传原文、URL、IP。选择可读取且解析正常的文件后接入，Client 会重启。容器内日志继续使用原有采集路径；不将所有容器日志当宿主机路径。

## 服务探测

配置节点侧 HTTP/HTTPS 或 TCP 地址，不允许 URL 内凭据。HTTP 不跟随跳转，只读取响应头；HTTPS 验证证书与主机名，证书剩余少于 14 天为警告，验证失败为危险。默认延迟警告 1000ms，可通过 API 调整。每节点最多 20 个探测，四并发、有连接/读取超时；同主机 DNS 解析仍依赖操作系统解析器。

## 管理升级与回滚

仅主机部署且支持 systemd 的新版 Client 可托管升级。目标固定为该 fork 的 `origin/main` SHA；版本必须等于 Server 已部署版本。节点复验 origin URL、SHA、VERSION 与本地工作区，任何不符均不执行。第一个节点为灰度，上报目标版本后才能推广。main 变化后未升级节点拒绝旧任务，需新建发布。

首次管理升级会停用节点原来 15 分钟无条件升级定时器，避免越过灰度；保留 `/opt/narwhal-monitor/client-previous`，权限 0700，里面的 env 为 0600。升级由独立 systemd 服务执行，安装失败恢复上一版。面板的「回滚」只恢复本地保留版本，不接受任意命令/下载地址。回滚后依然保持托管模式；若退出托管，人工重新运行 `scripts/setup-auto-update.sh client /absolute/repository`。

失败排查：`journalctl -u 'narwhal-managed-*' --no-pager` 和 Client 日志；执行 running 不等于升级通过，须查看签名版本报告。自动失败恢复后的文件/依赖和真实业务探测必须在灰度 Linux 主机核验。构建/模拟测试不能替代生产验证。

## 备份与恢复

定时备份默认关闭；启用后间隔 1-168 小时，保留 1-30 份。SQLite online backup 包含 WAL 中已提交数据，随后 integrity_check 与 SHA256；备份位于数据目录 `backups/`，每份 0600。备份保存数据库内的配置/用户/通知密钥，不包含外部 env、TLS 文件，后两者需独立受控备份。备份里有密钥，勿公开分享。

恢复不提供在线覆盖按钮，必须维护窗口操作：

1. 停止 Server 容器，确认没有其它写入者。
2. 将当前 `monitor.db`、其 `-wal/-shm`、外部 env/TLS 文件复制到新的 0700 目录保留，不直接删除当前版本。
3. 对选定备份运行 `sqlite3 SELECTED_BACKUP 'PRAGMA integrity_check'`，须返回 `ok`；检查 SHA256 和日期。
4. 在停服状态用备份替换目标 `monitor.db`，权限/属主与原文件一致。将目标原 `-wal/-shm` 移到上述保留目录，不能让旧 WAL 附着恢复数据库。
5. 启动 Server，核验管理员登录、采集新报告、策略/用户、服务状态和告警推送；失败则停服并恢复维护前整组 DB/WAL/SHM。

## 用户权限与审计

HTTPS 必须开启（Basic 认证并非加密）。原环境管理员保持可登录，不允许数据库用户覆盖同名账户；新增用户密码至少12位，scrypt 哈希。operator 可执行诊断/处置，不能管理用户/主机配置/升级/备份；viewer 只读且不能读取含密钥配置。权限校验覆盖旧 API，不依赖按钮隐藏。

变更记录身份、方法、路径与 HTTP 结果，不记录请求体、授权头、查询字符串；审计 180 天/最多 20000 行。管理员改名/删自己不支持，以免锁住面板。用户/策略配置本身是保留配置，不按遥测周期清除。
