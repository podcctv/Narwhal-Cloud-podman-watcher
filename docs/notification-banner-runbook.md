# v1.7.1：登录提示与买家通知

## 登录提示

- 只修改容器登录后的 `/etc/motd`，不修改 SSH 认证、端口或登录前 Banner。
- 仅更新 Narwhal 标记块，保留原提示。原子替换并读回校验；符号链接、异常文件和权限失败均报告失败，不伪报成功。
- 状态为风险存在、执行后待复查、证据不足、复查通过或复发。执行成功不是复查通过；恢复需要两次新鲜报告，容器缺失或认证未知不能证明恢复。
- 显示版本、事件 ID、UTC 采样时间；去除控制符并遮盖常见密钥字段。默认纯文本、不闪烁，按中文字符宽度换行。
- `SECURITY_MOTD_LANGUAGE=zh|en`、`SECURITY_MOTD_WIDTH=40..100`、`SECURITY_MOTD_COLOR=true` 可调整展示。颜色默认关闭，并尊重 `NO_COLOR` 和 `TERM=dumb`。
- 状态保存在 `SECURITY_MOTD_STATE_FILE`（默认 `/opt/narwhal-monitor/motd-state.json`），最多 1000 个容器、每容器 3 个事件。默认保留 24 小时，最多七天。
- 报告中的 `security.motd_delivery` 区分写入结果、持久化结果及登录机制检查。`login_display=configured` 只是配置检查，不是用户确实看见提示的证明；非交互 SSH 通常不展示 MOTD。

## 买家通知

1. 系统设置中保存 HTTPS API 地址与密钥。密钥只留在主控，不再下发 Client。
2. 在“买家推送记录与收件范围”登记精确的主机、运行时、项目、容器，绑定托管机器 UUID 与买家 `user_id`。不要猜测机器或买家身份。
3. 默认定向买家；整机广播需明确确认。无映射时进入“缺映射”，不请求 API。
4. 预览不发送、不验证连通性；真实测试需确认显示的收件范围，并占用相同机器冷却窗口。
5. 报告入库只排队，后台服务投递。事件及机器冷却持久化；默认一台托管机器 24 小时一条。摘要最多八个事件、1900 字符，只确认实际包含的记录。
6. 429 尊重 `Retry-After`；5xx 有限退避，最多五次。其他 4xx 失败；超时或发送进程中断标记“结果不确定”，不自动重发。人工补发需确认可能重复的风险，仍受最新事件、映射及冷却校验约束。
7. 状态、等级或事件轮次改变会取消旧待发内容。主机离线暂停发送；手动关闭不宣称复查通过。历史关闭记录不会在迁移时触发恢复通知洪峰。
8. 待发最多 10000 条、期限七天；终态记录保留九十天，每轮有限清理。上游是否支持幂等键未获证明，不能保证端到端严格一次或买家实际阅读。

## 升级与排障

- Server 与 Client 均需升级。旧 Client 保持报告兼容，但新 MOTD 模块只在新 Client 生效；安装及受管升级脚本已复制并校验该模块。
- 先备份 SQLite（使用在线 backup，包含 WAL 数据）、当前镜像与配置；确认新镜像内 `NARWHAL_VERSION` 与仓库 `VERSION` 一致后再替换主控。
- 不重写其他服务的 Caddy 路由。升级后检查认证 API、队列表、报告持续入库及前端资源。
- Cloudflare 403、401、缺映射和未知结果应先在上游排查，不能靠盲目重试证明发送成功。密钥和实际收件人不要写入日志、提交或评审提示。
- v1.7.1 本地 Windows 测试 242 项（七项 POSIX 测试跳过）；Linux 隔离环境 242 项全部通过。生产推送链路还须依据现场 API 权限和真实映射单独验证。
- v1.7.2 补齐容器化 Client 的 `security_banner.py` 镜像复制，并增加打包回归检查，避免主机安装正常但 Client 镜像缺模块。
