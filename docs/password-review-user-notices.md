# 密码人工评估与用户提醒（1.7.39）

## 认证与密码强度分开

`socks_password_review` 表示 SOCKS5 握手已确认要求认证，但无法可靠判断密码强度。
`socks_auth_unknown` 仍表示握手结果未知。二者均不作为自动停止依据。
既有已确认无认证/弱密码策略保持不变；本功能不将新采集的 GOST 密码组成自动升级为弱密码结论。

节点只读取识别到的进程配置（每文件最多 256 KiB），在本地统计内联入站密码。
支持 Xray/V2Ray、sing-box JSON/JSONC、GOST v2 入站 URL/serveNodes、GOST v3 services 的 JSON/YAML 内联 handler.auth、3proxy CL。
不统计出站链密码。最多展示 20 个账号，不包含账号名、密码原文、字符顺序、部分密码或凭据哈希。
长度按字符数计算；大小写、数字及符号按 ASCII 分类，其他字符/空白单独计数。
“重复数字”是同一数字在首次出现之后的重复次数之和，“最长连续重复”统计任意相同字符的最长连续段。

Dante 系统/PAM、3proxy 加密密码、外部 auther、环境引用、不可读/不支持的配置明确标注不可统计。
系统不会读取 shadow 还原密码、猜测密码或向 SOCKS 提交登录认证。配置统计不保证配置已经生效。

## 人工处置

活动告警中可选择既有放行策略，或“人工决定停止”。停止指令绑定当前证据代次，有效期 15 分钟。
节点执行前重新采集 PID 启动代次、配置文件元数据、监听端口及认证握手。
混合业务、内部回环、采样缺失/截断、证据变化、Docker notice-only 均不允许本入口停止。
仅执行明确的进程/所属服务定向停止，不停止整个容器，也不建立持续弱密码拦截策略。
一次人工确认不允许自动处置后续的新代次；停止回执仍须两次新采样复查，不能把未知认证判为恢复。

## 通知用户

总览安全告警和告警历史均有“通知用户”。先预览内容、收件范围与两条通道，再确认排队。
使用服务器已有通俗通知模板；密码组成属于管理员审核信息，不进入买家消息或 SSH 提醒。
密码待人工评估告警不会自动创建买家推送，只能由管理员明确点击“通知用户”触发；其他已确认风险仍按原自动通知策略处理。

- Telegram：复用 Narwhal 买家通知 API 和精确 user_id；Telegram 绑定/实际分发由上游维护。API 已受理不等于 Telegram 已读。
- SSH banner：写入指定容器已有的 SSH 登录后终端提醒卡片，不改认证前 sshd Banner。下次节点采集下发，再下一次上报确认写入；不是即时在线弹窗。

两条通道独立记录 queued/blocked/succeeded 或 written/uncertain/expired。缺收件映射不会整机广播，SSH 可独立排队。
收件人固定在确认时，之后映射变化会阻止发送，需重新预览。请求 ID 幂等、容器两分钟限流，并复用整机投递冷却。
超时或发送进程中断属于结果不确定，不自动重发；429 有界重试。提醒有效 24 小时，记录保留约 31 天、总数上限 10000。
SSH 卡片预留最新人工提醒位置；“已写入”不表示用户已经登录阅读。禁用 banner 或旧节点未支持时不会伪造成功。

## 发布顺序

先升级主控，再升级 Client 并安装更新后的 requirements（新增 PyYAML 6.0.3）。旧 Client 不产生新证据，不能使用人工停止入口。
本地预览与测试只使用合成数据，不能证明生产节点写入或真实 Telegram 投递成功。
