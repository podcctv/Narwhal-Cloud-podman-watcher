# 容器准入保护（1.7.44）

1.7.45 加固：首次规则写入失败或重启后按期望配置重试；完整规则指纹检测漂移（不把动态计数当成漂移）；完整运行时响应确认网络结构变化时撤回旧的专属规则，避免旧地址影响其他实例。普通缺失采样不会撤回保护。

仅作用于已核实独立网络及稳定身份的 Incus、Podman 容器，不处理母鸡服务或母鸡 Docker。私有 nftables 表只挂 FORWARD，按容器地址及已核实转发接口匹配；不改 INPUT/OUTPUT，不清空现有规则。不支持的网络结构显示未确认，不按地址猜测执行。

## 入站来源

- TCP/UDP 入站共享 5 个来源名额，IPv4/IPv6 合计，IPv4-mapped IPv6 去重。
- 保留先观测到的 5 个活跃来源，第 6 个及后续来源的数据包立即丢弃并告警；不全局封禁来源 IP。
- 首次启用没有历史到达顺序证据时，采用首次完整内核采样的顺序，随后按准入观测顺序记录。不能将该顺序宣称为历史真实先后。
- 已建立 TCP 连接与最近 90 秒有流量的来源占用名额；来源不再活跃后释放，后续来源按到达顺序进入。首次观测时间及名单持久化，Agent 重启不任意轮换名单。
- 来源是网络层可见对端，不从 HTTP 转发头推断真实用户；ICMP/IPv6 邻居发现不占业务来源名额。出站连接的回包不计入入站来源。

## TCP 并发

- 节点独立采样，计划间隔 10 秒；采样间隔超过 30 秒或身份变化，连续计时重置。主控离线不影响本地执行。
- 已建立及握手中的 TCP 严格超过 1000，连续有效采样满 120 秒，将新连接准入上限设为 500，最少保持 1800 秒。不把 TIME_WAIT 或 UDP socket 计入该并发数。
- 已有连接不会为达到 500 而被批量杀掉；新连接由串行决策及待握手预留名额防止突发超发。
- 到期仍 ≥500 或仍有持续超额需求，每轮只追加一次 1800 秒。不会每次采样都追加。
- 本轮期限到达，且有效采样严格低于 500 至少 120 秒、没有持续拒绝需求，才解除。采样缺失、进程重启或主控断线不视为恢复，也不盲目到期解除。
- 原有 2000/5 分钟停机保护在升级后的节点使用 TCP 活跃连接口径；计数口径变化不能借用旧的持续时间或旧停机指令。

## PasarGuard Node

依据官方镜像仓库（`pasarguard/node`、`docker.io/pasarguard/node`、`ghcr.io/pasarguard/node`），或 ELF Go build info 的 `github.com/pasarguard/node/cmd/node` 身份处理，不按通用 `main/node/xray` 名字杀进程。

仅停止确认归属的进程，清理其可证明归属的 systemd/OpenRC/supervisor/cron 启动项及程序。外层专用 Podman 服务停止并取消自动重启，保留容器及数据；Incus 外层实例不删除。内层 Docker 只有证明 dockerd 属于该客户实例、且不是母鸡挂载的 socket，才允许移除其中的禁止镜像服务；不删除数据卷。

原生清理保留私有恢复文件于客户实例的 `/var/lib/narwhal-disabled-pasarguard`。清理失败或复查仍有进程时不宣称成功。重新外部部署的服务会在后续扫描中再次检测。

## 状态、通知与回滚

Telegram、买家推送、SSH 登录 banner 均尽力送达，不阻塞本地保护。不得以测试为由向真实买家发送通知。面板展示保留/拒绝来源、TCP 上限、复查时间、追加次数及未确认状态。节点每 30 秒同步当前状态，数据库按实例覆盖写入，不无限追加采样；过期状态清理。

主机依赖：`nftables`、`libnetfilter-queue1`、`iproute2`（安装器补齐）。缺少依赖、接口归属不明或执行读取失败均不能显示保护已确认。

显式开关：`SECURITY_ADMISSION_ENABLED`、`SECURITY_PASARGUARD_BAN_ENABLED`，均默认 true，且服从 `SECURITY_MONITOR_ENABLED`。禁用开关不会自动删除已经存在的保护规则；需要显式受控回滚/卸载。

规则恢复记录为 `/var/lib/narwhal-monitor/admission.json`，权限 0600，不含密码或配置正文。受控回滚及卸载先停止 Agent，再用已安装的 `admission_guard.py --release-all` 清理恢复记录所列的专属表，不移除其他防火墙规则。直接回滚旧 Python 文件而不清理专属队列规则会遗留阻断，不受支持。

## 验证

`tests/test_admission.py` 覆盖阈值边界、缺失采样、重放、重启、续期、来源顺序、并发预留、签名与实例绑定、覆盖写入，以及实际裁剪 Go ELF 的识别。

`tests/admission_linux_probe.py` 必须在独立 `unshare --net --mount` 命名空间运行，验证桥接转发、IPv4/IPv6 共用 5 个来源、出站回包、无关目标及 500 条真实 TCP 连接的准入上限，不使用生产容器制造流量。CI 运行该测试。桌面/移动端合成页面测试不发送真实处置或通知。
## 节点自动跟随主控（1.7.47）

托管升级关闭节点原来的无条件定时器后，由主控接续负责更新。主控仅使用运行镜像内嵌的固定构建 SHA，并核验其仍是已发布 main 且 VERSION 一致；GitHub 不可验证时保留现状，不下发未知版本。

每 3 分钟协调一次：优先选择已运行较新版本的在线节点灰度，收到绑定节点身份的健康版本报告，再等待至少 2 分钟后的新报告，才按最多 3 台同时执行推广。离线节点不排超时任务，恢复上报后补升级。失败退避重试最多 3 次，耗尽后显示失败，需人工排查；不会无限重启。高于主控版本的节点不降级。

运维中心“节点升级”可以暂停或开启自动跟随。人工回滚会对该节点建立持久暂停，必须在页面明确恢复自动跟随后才允许再次自动升级。人工创建的当前版本灰度仍由人工推广，不被自动接管。每个版本保留发布历史和实际版本验证结果。
