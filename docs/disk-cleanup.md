# 安全磁盘清理（v1.7.23）

入口：运维中心 → 存储管理 → 宿主机与容器安全磁盘清理。所有已有/新节点默认关闭自动删除，升级不会清理现有文件。管理员可先扫描，再确认清理，或逐主机启用自动策略。查看账号仅能读取结果，操作员不能启用或执行清理。

## 自动策略与提醒

- 默认日志保留 14 天（可设 14–90 天），每个目标清理间隔 24 小时（可设 6–168 小时）。自动模式不需要磁盘先满才运行；开启后按周期维护。
- 每轮最多宿主机/容器合计 5 个目标、1,000 个文件、512 MiB 文件占用；单目标遍历最多 20,000 条目和 20 秒，开放文件检查另有预算。未完成的过期文件留待后续轮次，不能为释放更多空间扩大范围。
- 自动模式轮转所有受监测的 Incus / Podman 容器，新容器在 Agent 下一轮发现后自动纳入。手动扫描仅为宿主机及最多 4 个容器；可关闭容器选项仅扫描宿主机。Docker 保持项目原有仅提醒模式，不自动处理其文件。
- 宿主机卡片独立检查根分区与已配置的数据分区。新鲜采样达到 **90%** 时显示使用率/可用空间及不足提醒；清理完成不消除仍然存在的磁盘压力。采样过期不作为当前磁盘事实。无容器的节点可在存储管理面板查看根分区。
- 记录包含扫描候选、已删除文件占用、实际可用空间变化、前后使用率、跳过/错误/预算限制。文件占用移除不等于物理磁盘立即释放：镜像层、打开文件、其他进程写入都可能影响结果。网页不把排队 ACK 或只读扫描显示成清理成功，时间为北京时间。

## 固定允许范围

不接受自定义 shell、任意路径或删除命令。清理器不运行用户提供的 Bash 脚本，也不安装 guest 工具或重启服务。

| 类别 | 可清理文件 | 最短保留 |
| --- | --- | --- |
| 下载包缓存 | apt `archives/*.deb`、apk `*.apk`、pacman `*.pkg.tar.*`、dnf/yum 有界目录内 `*.rpm` | 1 天 |
| 归档系统日志 | 固定 syslog/messages/daemon/kern/debug/dmesg/boot 的编号或日期归档 | 策略期限，至少 14 天 |
| Web 归档日志 | nginx/apache2/caddy 固定 access/error 轮转文件；Caddy 标准日期归档 | 同上 |
| journal 归档 | machine-id 目录内带 `@` 的 system/user 归档 journal；不碰活动 `system.journal` | 同上 |
| 崩溃文件 | `/var/crash` 的 crash/upload 文件及标准压缩 coredump | 同上 |

年龄以 mtime、ctime、atime 中最新时间判断，不能通过只修改 mtime 将新文件变成过期文件。仅枚举固定允许目录的元数据，不读取文件内容、不上传文件名；记录仅为类别、目标身份和数字汇总。

**永不自动删除**：停止或运行的容器、镜像、pod、网络、卷、Incus 快照/备份/底层存储、数据库、客户目录、普通 `/tmp` 内容、独立 auth/secure/audit 日志、Narwhal 取证/恢复记录、软件依赖。不会 prune、autoremove、truncate，也不会覆盖 logrotate、journald 或 Docker 配置。journal 的旧系统归档可能包含认证事件，统一按保留期限处理，不能理解为永久保留全部 journal。

## 文件系统和身份保护

要求原生 root 宿主机 Agent，不支持在 Docker/Podman 容器内对宿主机自动清理。容器不需要 Python、Bash、find 或日志管理工具：从内核 `/proc/<init-pid>/root` 打开目录 FD，仅在该根内处理固定规则。

- 绑定 Incus `volatile.uuid` / Podman 完整 ID、init PID/start ticks、根目录设备/inode/mount ID；同名重建、重启/根变化不沿用旧扫描。
- guest 的嵌套挂载（包括同设备 bind）、主机 PID namespace/根文件系统、符号链接、硬链接、活动/打开文件、无法证明安全的目标均跳过。独立挂载的容器日志/缓存也会保守跳过，而非误删宿主或共享目录。
- 网络隔离 journal 中的容器不清理，保留证据。受保护的管理容器以及 Podman 共享/特权/设备直通拓扑也跳过，不能标为已清理。
- 单工作线程、进程级文件锁、私有原子状态和动作 ID 去重；重启后未完成任务标为中断，不自动重放。删除中身份失效立即停止并保留已经删除的准确计数，不伪报未处理或全成功。
- 手动清理要求 15 分钟内安全完成的扫描、管理员确认、相同节点和相同目标。部分扫描只允许处理其中安全完成的目标，其他目标仍跳过。

节点保留最近 20 次结果，服务端历史保留 30 天并设总条数上限；审计不记录请求正文、凭据或文件内容。关闭策略阻止后续自动删除，不恢复已删除的归档/缓存。升级回滚保留旧程序与配置，但不能恢复已删除文件，因此生产部署默认保持关闭。

## 验证

`tests/test_disk_cleanup.py` 覆盖安全目录/符号链接/硬链接/挂载、开放文件、保留期限、预算、目标变更、去重/中断、鉴权/节点绑定及签名回执。Linux 才运行内核 FD 检查，Windows 的平台跳过不替代 Linux 证明。

`python3 scripts/verify-disk-cleanup.py --run --image <本地已有 Python 镜像>` 仅创建随机命名的独立测试容器和临时目录。使用合成文件及仅对该测试 root FD 前移的测试时间验证实际删除、活动文件与 bind 保护；生产接口不接受测试时间或自定义 root。容器 PID/保留文件 SHA 保持，结束删除精确自建资源，不下载镜像、不清理生产文件。

`python -m tests.disk_cleanup_preview` 与 `node tests/test_disk_cleanup_ui.cjs` 为 loopback 合成网页演练：真实登录/鉴权、90% 提醒、320/375/768/1440 布局、确认/Escape、真实排队 ACK、过期拒绝、只读账号；不会连接真实 Agent 或机器人。
