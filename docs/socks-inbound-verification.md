# SOCKS 入站、认证与处置边界（v1.7.34）

## 修复

- Xray/v2ray、sing-box 使用结构化 JSON/JSONC 解析，只认 SOCKS/mixed 入站。SOCKS 出站、其他协议的账号、密码不构成 SOCKS 入站风险。
- 配置来自实际进程 argv 的绝对 JSON 路径；不把某个配置的认证状态分配给其他进程。解析失败、超限、动态端口没有否定/恢复证明效力。
- 实际监听必须匹配进程 PID、端口和绑定地址。同一 Xray 的 VLESS:443 不继承 SOCKS:1080 的认证状态。
- GOST 仅从 -L 获取 SOCKS 监听证据，-F 出站链不推断无认证。
- v1.7.34 追加防御：异常/非整数/范围端口保持未核实；配置目录和配置外其他实际监听否定“单用途进程”的整进程停止证明，防止编辑未重载或动态监听造成误停。接续 main 的 v1.7.33 业务同步补丁，不覆盖并行发布。
- 回环监听按内部依赖处理；只有精确指向该回环地址/端口的非回环代理转发才改变暴露判断。相同端口但目标地址不同不算转发证明。非回环包括局域网可达，不宣称已验证公网路径。

## 有限协议检查

仅对已观察到的候选 TCP 监听，在对应容器网络命名空间内发送 SOCKS5 方法协商 `05 02 00 02`。不发送账号密码，不做 CONNECT/UDP ASSOCIATE，不代理访问外部站点。

每实例每轮最多两次，4秒内允许启动，单子进程硬超时3秒；因此两次最坏约6秒。失败三次后该身份/端点暂停探测30分钟，缓存最多512项。进程/实例身份变化建立新记录。暂停不是安全结论；原因与重试间隔上报。要求密码认证只证明认证方法，不证明密码强度。

## 自动处置

已确认网络可达且无认证/弱密码的单用途 SOCKS 进程仍可自动停止，保留原有 PID 精确处置与回执。回环依赖、证据未知、超时、缺少命名空间访问时不自动停止。

混合协议进程仅告警，原因 `mixed_or_unverified_process_scope`，不杀整个 Xray/sing-box。按端口实施持久、可逆隔离还需单独实现，不能把“没有停止”报告成“已处置”。新告警声明精准作用域时，Server 不再从展示文案/旧字段补猜一个被故意留空的停止目标。

## 兼容、发布与验证

新增 socks_detector.py 已纳入 Client Docker 镜像、主机安装与受管升级/回滚模块清单。原始配置和凭据只在本地内存中解析，不进入遥测、评审提示或日志。

回归覆盖出站误报、入站间字段污染、旧 accounts 字段、JSONC、IPv4/IPv6 回环、地址精确转发、混合引擎、专用代理自动处置、认证未知、失败退避、分片握手、打包和服务端旧文案回填边界。Jev只辅助复核脱敏规则，不能替代代码测试和现场验证。

上线先升级主控，再升级目标 Client，保留原模块/环境与数据库在线备份。检查新鲜签名报告、旧误报告警自然结束、业务 VLESS 监听与进程不变。不能靠人工忽略/删除告警证明修复。
