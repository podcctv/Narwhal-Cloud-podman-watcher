# 用户异常排查（方案一）

入口：主导航 → 用户排查。默认选第一台母鸡，查询最近30天；支持7/30/90天、用户/容器/异常名称检索、用户明细、独立事件分页与容器历史侧栏。

## 统计口径

- 顶部始终是所选母鸡、时间范围的整体统计；搜索只筛选明细，不改变整体集中度提示。
- 已监测容器按实例身份去重。身份包括稳定node_id（没有时使用host_id）、运行时、项目、容器名，以及可用的实例ID/创建时间。
- 同名重建只有在实例ID/创建时间可区分时才分开；没有证据时界面明确提示不能声称已区分。
- 用户内异常率 = 有异常记录的实例 / 此用户在窗口内有观测记录的实例。归属转移时同一实例可出现在多个用户下，因此各用户行不可简单相加当作整机总数。
- 缺少安全评估的实例显示未评估，不把缺数据显示为0%风险。未知归属不计算用户异常率。
- 集中度 = 此用户异常实例 / 已归属异常实例，衡量集中线索，不是违规概率、恶意评分或封禁依据。
- 独立事件沿用探测器的规则指纹与episode起点，持续重复上报不增加事件数；不同规则可形成多个事件，但异常容器只计算一个。历史不完整的旧告警不计入独立事件数。
- 已放行/本次忽略的记录仍可查看，但不计入异常集中度。
- 母鸡公共告警单列，不套用某个买家；外部攻击/扫描信号不代表用户是攻击者。出站网络异常也只提供排查线索。

## 历史与证据

新事件只在首次捕获时冻结精确、有效、单用户实例映射；后续买家变更不改写旧事件。过期自动映射、整机广播、没有映射或旧事件无法证明当时归属的记录均标未知，不事后猜买家。

记录首次检测、最后异常样本、开始留存时间、首次值/阈值、最近值/阈值、状态/等级/阈值变化、处置回执。保留进程与监听关系、认证类型和白名单事实，不复制原始配置、密码或Token。不同时间点的数值不推算连续异常时长。

“已执行，待复查”“等待新采样复查”“复查通过”“告警结束，未验证”严格区分。单纯收到一份干净样本不能声称执行了关闭操作。复查使用现有buyer_checks/ops_rechecks证据；缺少采样或重建身份信息时明确保留未知。

这是新增历史：部署前已被覆盖/清理的事件无法恢复，部署后逐步积累。不修改Client接口、不改变通知推送或自动处置策略。

## 存储边界

- 新增表独立于短期原始reports，最多保留90天。
- 硬上限：20,000事件、100,000按实例/归属/自然日的观测、60,000状态记录；单事件最多20条状态记录（首条加最近19条）。
- 满上限时限制新增历史写入，已有事件仍可更新；标记覆盖缺口。后台按批清理，不做在线全库VACUUM。
- 达到容量限制后实际可查询天数可能少于90天，不宣称所选窗口完整。
- node_id对应主机改名时更新显示名但不改实例身份或冻结的用户归属。人工删除主机时清理对应新历史；自动离线清理不提前删除保留期内的调查历史。

单元/接口覆盖：事件去重、复发、阈值快照、用户转移、过期映射、同名实例重建、公共告警、放行排除、检索与分页、回执留存、乱序报告、安全未评估、写入硬上限、清理、改名、report入口与查询参数。

本地示例：`python -m tests.investigation_preview`，仅监听127.0.0.1:8786，使用临时数据库、虚构用户和示例告警。不要在公网/生产运行此预览包装器。
