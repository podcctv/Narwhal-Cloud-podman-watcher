# 连续连接超限：保护优先（1.7.41）

当前连接数严格大于 2000，连续有效采样覆盖至少 300 秒后立即排队关闭容器，不删除数据。通知独立尽力发送；缺少收件映射、API 配置、发送失败、超时或通知队列异常都不能阻止停机保护。

统计口径为 TCP 各状态 + UDP socket 总数，不是用户数或 HTTP 请求数。1000 的严重告警线不变。五分钟窗口至少两个新鲜有效样本；同一容器/网络代次、没有回落到 2000 或以下，最大采样间隔 360 秒。缺失、过期、重启、口径不完整均重建窗口；乱序不延长窗口。策略变化不沿用旧告警时长。

保护动作先入库，再安排定向通知；队列错误通过保存点隔离。报告处理不访问通知网络。通知回执永远不能创建停机动作，避免迟到回执重复关闭容器。通知不广播，超时结果不确定不盲目重发。API 受理不等于用户已读。SSH banner 独立写入，停止后无法登录时不承诺 banner 已送达。

节点执行前仍检查当前连接数、容器代次、证据时效；已恢复、重建或过期拒绝执行。Docker notice-only 保持不自动停止。排队不等于关闭成功，实际结果保存在动作回执。

生产配置：CONNECTION_STOP_THRESHOLD=2000、CONNECTION_STOP_DURATION_SECONDS=300、CONNECTION_STOP_MAX_GAP_SECONDS=360、CONNECTION_AUTO_STOP_ENABLED=true。已有环境配置必须显式同步。

## 恢复时长

每轮告警以 first_seen 为起点，两次新报告复查通过后冻结首次确认恢复时间，展示持续时长及恢复时间。后续上报不会延长时长，复发建立新轮次。缺少容器或认证证据不算确认恢复。人工关闭、待复查、旧记录未留存恢复时间分别标注，关闭前时长不冒充恢复时长。仅在已有每告警一行的 buyer_checks 增加时间列，不引入无限增长明细表。
