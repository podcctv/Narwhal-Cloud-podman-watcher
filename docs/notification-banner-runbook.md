# 登录提示与买家通知（v1.7.4）

## 登录提示

- v1.7.8：默认闭合品牌卡片由主机 Agent 每轮刷新；新建并运行、被 Agent 发现的受监控 Podman/Incus 容器在下一轮自动安装，无需修改创建模板。停止容器待启动后安装；显式关闭安全监测/登录提示及 Docker 仅提醒模式仍保留原策略，不擅自越权写入。
- v1.7.9：混合运行时宿主机按容器的实际 runtime 选择 Banner 写入命令，不再回退到宿主机默认 Podman；运行时缺失或不匹配时拒绝写入其他运行时。
- 默认显示「弗兰克托管 / FLANKER HOSTING」闭合卡片和频道 `https://t.me/flanker_channel`；无告警也保留品牌提示。不修改系统 hostname、SSH 认证、端口或登录前 Banner。
- Agent 更新 `/etc/narwhal-banner.sh`，交互会话按 `stty size` 选择 12..100 列的有界预排版；容器拒绝窗口尺寸 ioctl 时使用交互 shell 的 `COLUMNS`（无有效尺寸时回退 80）。宽窗口显示轮廓大字，窄窗口使用紧凑标题。中文按显示格宽度补齐，颜色控制码不计宽度。极窄（小于十二列）不展示卡片，避免折行。
- `/etc/profile.d/90-narwhal-banner.sh` 用于登录 shell，`/root/.bashrc` 的 Narwhal 标记块用于当前网页控制台的 root Bash。仅交互且 stdout 为 TTY 时显示；同一 shell 不重复展示，脚本/SFTP 不输出。其他用户的非登录 shell、非 Bash 网页 shell 不保证自动展示，需控制台启动端配合。
- 不要求容器安装 Python；使用已有 sh/awk/stty/date/base64/gzip/cmp。缺工具或拒绝写入时报告 shell 安装失败，并回退原 `/etc/motd` 路径。成功安装 shell 提示时移除旧 MOTD 的 Narwhal 块，保留用户内容，避免 SSH 同时展示两份卡片。
- 仅更新 Narwhal 标记块，保留原提示。原子替换并读回校验；符号链接、异常文件和权限失败均报告失败，不伪报成功。
- 状态为风险存在、执行后待复查、证据不足、复查通过或复发。执行成功不是复查通过；恢复需要两次新鲜报告，容器缺失或认证未知不能证明恢复。
- 显示版本、事件 ID、UTC 采样时间、告警原始描述以及已采集的数值/阈值；去除控制符并遮盖常见密钥字段，不编造缺失数据。默认无异常为绿色，警告/待复查为黄色，严重活动风险为红色；提示快照超过十五分钟显示「当前状态未知」。
- `SECURITY_MOTD_LANGUAGE=zh|en`、`SECURITY_MOTD_WIDTH=12..100` 可调整回退 MOTD；回退路径默认纯文本。交互卡片默认着色，支持会话中 `SECURITY_MOTD_COLOR=false`、`NO_COLOR`（包括空值）和 `TERM=dumb` 禁用颜色。
- 状态保存在 `SECURITY_MOTD_STATE_FILE`（默认 `/opt/narwhal-monitor/motd-state.json`），最多 1000 个容器、每容器 3 个事件。默认保留 24 小时，最多七天。
- 报告中的 `security.motd_delivery` 区分写入结果、持久化结果及登录机制检查。`login_display=configured` 只是配置检查，不是用户确实看见提示的证明；非交互 SSH 通常不展示 MOTD。

## 买家通知

1. 系统设置中保存 HTTPS API 地址与密钥。密钥只留在主控，不再下发 Client。
2. 在“买家推送记录与收件范围”登记精确的主机、运行时、项目、容器，绑定托管机器 UUID 与买家 `user_id`。不要猜测机器或买家身份。
3. 默认定向买家；整机广播需明确确认。无映射时进入“缺映射”，不请求 API。
4. 预览不发送、不验证连通性；真实测试需确认显示的收件范围，并占用相同机器冷却窗口。
5. 报告入库只排队，后台服务投递。事件及机器冷却持久化；默认一台托管机器 24 小时一条。摘要最多八个事件、1900 字符，只确认实际包含的记录。
6. 429 尊重 `Retry-After`；5xx 有限退避，最多五次。其他 4xx 失败；超时或发送进程中断标记“结果不确定”，不自动重发。人工补发需确认可能重复的风险，仍受最新事件、映射及冷却校验约束。
7. 状态、等级或事件轮次改变会取消旧待发内容。主机离线暂停发送；手动关闭不宣称复查通过。历史关闭记录不会在迁移时触发恢复通知洪峰。
8. 待发最多 10000 条、期限七天；终态记录保留九十天，每轮有限清理。上游是否支持幂等键未获证明，不能保证端到端严格一次或买家实际阅读。

## 升级与排障

### v1.7.4 通知证据与持续带宽

- 买家映射每五分钟同步上游完整机器/实例列表，仅按唯一实例 UUID、运行时和精确本地项目匹配；重复身份、缺买家、已删除实例不猜测、不整机广播。自动映射十五分钟过期，手工禁用及手工范围保持不变。节点名称来自上游机器名称。
- 普通告警保存采样时数值和生效阈值；策略信号同时保存 values/thresholds。通知换算 Mbps、百分比，提供已采集的来源 IP 和请求数量，不以当前配置覆盖历史阈值。
- 监听端口来自 ss 的实际进程 PID 归属，不将实例所有端口分配给 SOCKS 或面板。认证未知但实际监听的 SOCKS 仅提醒核查，不视为空密码，也不自动处置。
- 清理脚本回传实际进程、服务配置、配置文件、程序文件、启动项的逐项完成/失败记录。单次最多二十项，通知展示前六项并提示其余记录已保存。旧 Client 无清单时明确显示清单未上报，不编造删除对象；停止实例明确表示“未删除实例”。
- 不产生或投递流量额度提醒，旧待发额度提醒取消；历史流量账本保留。持续带宽提醒使用实例实际带宽（上游实例元数据或精确容器策略），不继承主机网卡带宽，不猜测未知容量。
- 默认单方向平均占用达到 90%，有效累计流量计数器差值至少两段、连续覆盖十分钟时提醒；三十分钟升级为危险。收发方向不相加。断档、计数器重置、估算数据、带宽来源变化均重新计时；缺数据不是恢复证明。这是可调整的运维起步值，不是通用攻击判定阈值，不因此自动停机。
- Hysteria 2 至少三次有效采样且实际跨度达到 180 秒才触发原有限速策略。执行或解除失败不会伪报成功；连接保护停止实例后保存真实终态回执通知，不将排队状态当成执行成功。
- 完整通知保留检测时间和工单入口；摘要不截断单条通知，不将未包含的事件标为已发送。控制字符与常见凭据字段会清除/遮盖。

- Server 与 Client 均需升级。旧 Client 保持报告兼容，但新 MOTD 模块只在新 Client 生效；安装及受管升级脚本已复制并校验该模块。
- 先备份 SQLite（使用在线 backup，包含 WAL 数据）、当前镜像与配置；确认新镜像内 `NARWHAL_VERSION` 与仓库 `VERSION` 一致后再替换主控。
- 不重写其他服务的 Caddy 路由。升级后检查认证 API、队列表、报告持续入库及前端资源。
- Cloudflare 403、401、缺映射和未知结果应先在上游排查，不能靠盲目重试证明发送成功。密钥和实际收件人不要写入日志、提交或评审提示。
- v1.7.1 本地 Windows 测试 242 项（七项 POSIX 测试跳过）；Linux 隔离环境 242 项全部通过。生产推送链路还须依据现场 API 权限和真实映射单独验证。
- v1.7.2 补齐容器化 Client 的 `security_banner.py` 镜像复制，并增加打包回归检查，避免主机安装正常但 Client 镜像缺模块。
- v1.7.3 使用明确的 `Narwhal-Monitor/<version>` 请求标识与 JSON Accept 头。现场只读对照：默认 Python User-Agent 返回 403，应用标识返回 200；这仅证明机器列表读取成功，不代表实际买家通知已送达。
