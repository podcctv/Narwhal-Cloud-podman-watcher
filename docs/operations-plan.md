# 运维中心实施与验收

12 项按依赖分组上线：采集健康/处置复查/存储 → 流量账本/策略/基线/事件 → 日志/升级/可用性/备份/权限。

| 项目 | 实现合同 | 验收重点 |
|---|---|---|
| 1 健康 | 报告时间、来源、失败原因、修复建议；零值不代表缺失 | 旧 Client 明确 unavailable；超时 stale |
| 2 闭环 | 执行后等新报告复查；复发有界重试；失败可查看 | 同一身份与告警类型、最多两次复查重试 |
| 3 存储 | 按表占用、清理状态、小时/日汇总 | 原始数据清理后汇总仍在；汇总有保留上限 |
| 4 账本 | 累计计数优先，估算标注；日/月配额 | 重复报告、计数重置、采集间断不虚增 |
| 5 策略 | general/web/socks/hy2，主机/容器覆盖、预览、限时静默 | 不解除原有恶意进程/弱认证防线 |
| 6 基线 | 最近样本、至少 24 个、三次双信号偏离 | 初始样本不足不宣称异常；只告警不自动停业务 |
| 7 事件 | 按身份聚合异常/处置/复查/恢复 | 不混合运行时与项目；事件保留有界 |
| 8 日志 | Agent 发现路径和解析预览；确认接入 | 不上传原始含凭据日志；缺失/拒绝/解析失败分别显示 |
| 9 升级 | 固定提交、灰度、版本报告确认、失败/回滚 | 仅可信 origin 主分支；不接受任意 shell |
| 10 可用性 | 节点侧 HTTP/TCP/TLS 探测 | 超时与证书错误不当正常；探测有并发/时间上限 |
| 11 备份 | SQLite online backup、integrity_check、定时/保留 | 含用户和密钥数据库仅 0600；恢复需停服并备份当前版本 |
| 12 权限 | admin/operator/viewer、密码哈希、变更审计 | 所有旧 API 同样受保护；不记录密码/请求体 |

## 边界

这是一版完整可用的运维工作流，不替代运营商级抗 DDoS、精确计费或公网主动安全扫描。动态基线不用于停容器。网络账本在计数不可用时只是观测估算，不补算离线时段。节点必须更新 Client 才有新探测/日志/升级能力。
